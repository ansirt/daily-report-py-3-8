Ikhtisar Sistem Daily Report Scheduler

Aplikasi Daily Report Scheduler digunakan untuk mengotomatisasi ekstraksi data, transformasi ETL ringan, pembuatan laporan dalam bentuk berkas Excel (.xlsx), hingga pengiriman berkas ke alamat email tujuan secara berkala berdasarkan penjadwalan CRON[cite: 1].

Multi-Database

Dukungan penuh ke Oracle (cLIent/Native), MySQL, dan SQL Server (MSSQL)[cite: 1].

Alur Kerja Terintegrasi

Mendukung eksekusi skrip Python, API Get, Stage DB, dan Export/Import CSV[cite: 1].

Distribusi Email

Kirim laporan Excel langsung via SMTP lengkap dengan perulangan log dan penanganan error[cite: 1].

1. Manajemen Koneksi Database

Koneksi dikonfigurasi pada menu Connections. Aplikasi mendukung validasi keamanan kueri agar secara bawaan hanya mengeksekusi perintah baca-saja (SELECT / WITH)[cite: 1].

Keamanan Write Access: Jika Anda bermaksud melakukan pengisian data staging atau manipulasi data melalui node db_write, opsi Allow Write pada konfigurasi koneksi tersebut harus diaktifkan secara eksplisit[cite: 1].

Parameter Utama Koneksi:

  • Tipe Database: Pilih antara oracle, mysql, atau mssql[cite: 1].
  • Host & Port: Port default standar (Oracle: 1521, MySQL: 3306, MSSQL: 1433)[cite: 1].
  • DSN (Oracle): Dapat digunakan opsional jika tidak menggunakan kombinasi Host/Port/Service Name[cite: 1].
  • Test Connection: Selalu tekan tombol ini sebelum menyimpan koneksi untuk memastikan autentikasi terverifikasi[cite: 1].

2. Membuat Job & Format Penjadwalan CRON

Setiap Job mewakili satu siklus pembuatan laporan yang berjalan otomatis berdasarkan format standar CRON Expression (5 segmen)[cite: 1]:

┌───────────── Menit (0 - 59)
│ ┌─────────── Jam (0 - 23)
│ │ ┌───────── Hari dalam Bulan (1 - 31)
│ │ │ ┌─────── Bulan (1 - 12)
│ │ │ │ ┌───── Hari dalam Minggu (0 - 6) (Minggu=0)
│ │ │ │ │
* * * * *

Contoh Jadwal Eksekusi:

0 7 * * * : Berjalan setiap hari pukul 07:00 WIB[cite: 1].
30 8 * * 1-5 : Berjalan pukul 08:30 WIB setiap hari kerja (Senin-Jumat)[cite: 1].

3. Fitur & Tipe Langkah (Query Nodes)

Satu Job dapat berisi beberapa langkah (nodes) pemrosesan data[cite: 1]:

sql / stage Ekstraksi Query

Mengeksekusi SQL SELECT dari database target. Tipe stage memungkinkan hasil query disimpan langsung ke tabel staging database tujuan[cite: 1].

py_script Custom Python Execution

Menjalankan manipulasi data menggunakan Pandas/Numpy secara otomatis sebelum output dibuat[cite: 1].

db_dump Utility Dump Database

Mengeksekusi backup/dump otomatis native utilitas database (seperti mysqldump atau expdp)[cite: 1].

api_get / csv_export Data Connector

Mengambil data dari REST API external atau mengimpor/mengeksport file CSV lokal ke pipeline job[cite: 1].

4. Sintaks Parameter Dinamis (sqlParam)

Gunakan variabel sqlParam pada SQL Anda. Sistem akan menggantinya sesuai Date Mode job (today / yesterday)[cite: 1]:

-- Query dengan tanggal dinamis harian:
SELECT branch_code, SUM(amount) AS total_sales
FROM transaction_logs
WHERE trx_date sqlParam
GROUP BY branch_code;

Penerjemahan Otomatis oleh Engine:

Oracle DB

= trunc(sysdate)

MySQL

= curdate()

SQL Server (MSSQL)

= cast(getdate() as date)

5. Pengaturan Email & Dynamic Placeholder

Anda dapat menggunakan tag dinamis pada **Subject**, **Filename Template**, dan **Body Email HTML**[cite: 1]:

{tgl}

25-Oct-26[cite: 1]

{tgl_title}

25-10-2026[cite: 1]

{hari}

Minggu[cite: 1]

{tgl_long}

25-Oct-2026[cite: 1]

Contoh Format Filename Template:
laporan_penjualan_{tgl_title} ➔ Hasil: laporan_penjualan_25-10-2026.xlsx[cite: 1]

6. Log Eksekusi & Pembersihan Berkas (Retention)

Sistem mencatat setiap riwayat eksekusi pada halaman Run Logs[cite: 1].

  • Fitur Re-send Email: Jika terjadi kegagalan jaringan saat mengirim email, Anda dapat menekan tombol Resend pada baris log tanpa harus menjalankan ulang query[cite: 1].
  • Pembersihan Berkas Otomatis: Berkas output laporan Excel disimpan di direktori server dan akan dibersihkan secara otomatis sesuai batasan Retention Days yang dikonfigurasi pada menu Settings (default: 30 hari)[cite: 1].
